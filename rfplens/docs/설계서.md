# RFPLens 설계서 (v0.1.0, rules-v1)

공공조달 공고 문서(공고문·과업지시서·제안요청서 등)를 **빠짐없이 읽고(판독)**, **지우지 않고 구조화(라벨링·단위 분할)** 하는 엔진.
demand_to_deal 프로젝트의 수요측 입력 데이터를 만드는 첫 모듈이며, 앱·웹 서비스에서 함수/HTTP로 호출할 수 있게 만든다.

- 학습 모델은 없다. **규칙 기반 알고리즘 + OCR 엔진(macOS Vision, 교체 가능)** 의 조합이다.
- 기원: 2025년 1월 나라장터 용역 공고 9,536건(파일 19,247개) 처리 경험(1배치, 2026-11-11).

## 1. 원칙
1. **자료가 있으면 무조건 읽는다.** 판독 실패 0을 목표로, 실패는 숨기지 않고 기록한다.
2. **내용은 지우지 않는다.** 과업/행정/서식 등의 구분은 삭제가 아니라 라벨이다. 걸러내기는 이후 분석 단계의 선택.
3. **형식은 내용으로 판별한다.** 확장자를 믿지 않는다.
4. **단계별 저장·재현성.** 판독(s1) → 문서유형(s2) → 구간 라벨(s3) → 단위(s4)를 따로 저장하고, 규칙은 버전 관리한다. 모델·분석방법이 바뀌어도 s4부터 다시 시작한다.

## 2. 구조
```
rfplens/
  api.py        공개 함수 read_file / read_bytes / read_notice / read_uploads / structure_notice / process_notice
  reader.py     문서 리더(디스패처): 형식 판별 → 판독기 → 재귀(zip·폴더) → 내장 이미지 OCR → 품질 판정
  detect.py     매직 바이트 형식 판별(drm, ole→hwp/xls/doc/ppt, hwpx, docx, xlsx, pptx, zip, pdf, image, hml …)
  readers/hwp.py       HWP 5.x 본문 레코드 판독(표 포함) + 배포용 문서 AES-128 해독
  readers/xmldocs.py   hwpx·docx·xlsx·pptx·hml
  readers/external.py  pdf(pdftotext + 무텍스트 쪽 OCR), LibreOffice 변환, hwp5txt
  ocr/          OCR 엔진 인터페이스(vision | tesseract | none), vision.swift
  quality.py    정리(clean)·깨진 문자 비율·상태 판정
  policy.py     판독 불가 처리(공고문만 불가 → 통과, 핵심문서 불가 → 대체 원문)
  sections.py   문서유형·제목 판별·고정 위계·구간 모드(라벨)
  units.py      요구사항 단위 분할·unit_id·공고 내 중복 표시
  rules/rules_v1.toml  키워드·위계·임계값(코드 수정 없이 조정)
  pipeline.py   공고 1건 처리, 배치 병렬 실행(read / structure)
  store.py      저장소 형식
  census.py     나라장터 전수 데이터 어댑터(대상 목록, 대체 원문 후보)
  verify.py     판독 검증(누락 파일·실패·부분판독)
  cli.py        명령줄
```

## 3. 판독 알고리즘(reader)
| 단계 | 내용 | 1배치 근거 |
|---|---|---|
| 형식 판별 | 앞 바이트로 판별. OLE는 내부 스트림으로 hwp/xls/doc/ppt 구분 | `.hwpx`인데 hwp, `.hwp`인데 hwpx, `.hwtx`인데 hwpx 등 약 40건 |
| hwp | BodyText 레코드(PARA_TEXT) 문서 순 판독. 표 컨트롤 안 문단 포함, 칸 3개 이상 표 셀에 `│` | hwp5txt는 표를 `<표>`로만 출력 → 문서 전체가 표인 경우 6자 |
| 배포용 hwp | ViewText 첫 레코드 256B에서 MSVC rand 마스크로 키 도출 → AES-128-ECB 해독 → 압축 해제 | hwp5txt는 해독하나 표 누락(3.8만→11.2만 자) |
| 대체 경로 | hwp 실패 → hwp5txt → LibreOffice 텍스트 | |
| hwpx/docx/xlsx/pptx/hml | XML 직접 판독(표 셀 표시) | |
| 구형 xls/doc/ppt | LibreOffice headless로 xlsx/docx/pptx 변환 후 판독(프로세스별 프로필) | xls 25건 |
| pdf | pdftotext 쪽별 → 공백 제외 20자 미만 쪽만 200dpi 렌더링 → OCR | 스캔 pdf 59건 |
| 이미지 | OCR | |
| zip·폴더 | 끝까지 재귀(최대 4단계), UTF-8 플래그 없는 파일명은 cp949 복원 | 압축 안 압축, 압축 푼 폴더 |
| 미상 형식 | LibreOffice 텍스트 변환 | |
| 내장 이미지 | 텍스트가 100자 미만이고 내장 이미지가 있으면 이미지 OCR(3KB 미만 제외) | |
| 품질 판정 | 한자·사용자정의·대체문자 비율 30% 초과 → 실패 | LibreOffice가 DRM 파일을 깨진 글자 3만 자로 '성공' 처리한 사례 |
| DRM | Fasoo(DRMONE)·MarkAny 등 헤더 → 실패(판독 불가) | 1건 |

상태: `성공` / `성공-짧은문서`(정상 판독, 원문 자체가 100자 미만) / `성공-대체원문` / `통과-공고문판독불가` / `실패`

## 4. 판독 정책(policy)
- 공고문 등 **비핵심 문서만 판독 불가**이고 같은 공고의 핵심문서(과업지시서·제안요청서)가 판독되면 → `통과-공고문판독불가` (이상 아님)
- **핵심문서가 판독 불가**이면 → 대체 원문 탐색: 같은 공고번호의 다른 차수 → 같은 수요기관·유사 공고명(토큰 자카드 ≥0.6 또는 포함관계)의 재공고, 공고일이 가까운 순. 같은 문서유형이면서 정상 판독되는 첫 파일. 출처(`substitute_from`) 기록.
- 후보 탐색기는 `candidate_provider`로 분리(서비스 환경에 맞게 교체).

## 5. 구조화 알고리즘(sections · units)
1. **문서유형**: 파일명(압축 내부는 내부 파일명) — 제안요청서(제안요청|RFP) > 과업지시서(과업) > 공고문(공고) > 기타
2. **줄 단위 판정**: 항목 기호 분리 → 제목 여부(핵심어 30자·줄 60자 이내, 번호 없는 줄은 핵심어 12자 이내, 서술 종결어미 제외) → 제목 분류(행정 > 과업 > 개요 키워드)
3. **고정 위계**: Ⅰ > 1. > □ > 가. > ○ > 1) > - > 가) > (1) > ① (출현 순서 기반은 목차·요약이 앞에 있으면 역전)
4. **구간 모드**: 과업 제목 이후 TASK(하위 제목은 유지) / 행정 EXCL / 붙임·서식 이후 HARD / 개요 CTX / 행정·개요 뒤 같은 수준 이상 일반 제목 NEUTRAL / 첫 제목 전 NONE. 표 셀(`│`)은 제목 판별 없이 현재 모드.
5. **라벨**: TASK=과업, NEUTRAL=일반, CTX=개요, EXCL=행정, HARD=서식·붙임, NONE=서두 — 모든 줄 유지(목차 줄만 생략)
6. **단위**: 항목 기호마다 새 단위, 연속 줄은 같은 라벨이면 이어붙임, 라벨 경계는 넘지 않음. 15자 미만은 같은 라벨 직전 단위에 병합, 800자 초과는 문장 경계 분할. 상위 제목 경로(path) 부착, 하위 항목을 가진 짧은 제목은 `is_title=1`.
7. **식별자**: `unit_id = <공고번호-차수>_<문서순번2>_<단위순번4>`(같은 규칙이면 재현). 공고 내 동일 문장은 `dup_in_notice=1`(삭제 안 함).

## 6. 1배치 결과(참고)
- 판독: 파일 19,247개 실패 0 (OCR 115개, LibreOffice 변환 25개, 배포용 해독 포함), 짧은 문서 2(비밀사업 안내문), DRM 공고문 1(핵심문서 판독 → 통과)
- 구조화: 단위 약 255만(라벨: 과업 78만, 행정 88만, 일반 49만, 서식·붙임 30만, 개요 7만, 서두 4만)
- 속도(8코어 Mac): 판독 약 6분/1만 공고(OCR 포함), 구조화 약 1분

## 7. 서비스 이식
- Python 패키지(`pip install -e rfplens[service]`), 웹 API 뼈대: `../service/app.py`(FastAPI: /v1/read, /v1/notice)
- 외부 프로그램: poppler, LibreOffice. OCR은 macOS Vision(기본) / 리눅스는 `RFPLENS_OCR=tesseract` + kor 데이터
- 설정: `RFPLENS_TMP`, `RFPLENS_RULES`, `RFPLENS_OCR`, `RFPLENS_OCR_BIN`, `RFPLENS_SOFFICE`, `RFPLENS_HWP5TXT`

## 8. 한계·향후
- 사용자 암호가 걸린 hwp, DRM 문서는 판독 불가(정책으로 처리)
- OCR 품질은 엔진 의존(표 구조는 줄 단위로 평탄화)
- 문서유형은 파일명 기준(파일명이 불명확하면 '기타')
- 구간 라벨은 규칙 기반이라 기관 서식에 따라 오분류 가능 → 내용은 지우지 않으므로 이후 라벨 규칙만 개선·재적용
- 향후: 라벨 분류기(학습형), 표 구조 보존, 공급측 Capability·매칭 모듈(demand_to_deal 형제 폴더)
